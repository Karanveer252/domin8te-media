## RPC contracts for the browser

All `security definer`, `search_path ''`, EXECUTE revoked from public and anon, granted to authenticated.

**`client_today_panel(p_tenant uuid default null) returns jsonb`**
Client: no argument (own restaurant). Staff (view as): pass `p_tenant`; a client passing it gets 42501.
```
{ day: 'YYYY-MM-DD',            // the restaurant's local today, always
  state: 'ready' | 'updating',  // updating = no ready row for today (not built yet, or it failed)
  tiles: [ { id: 'customers'|'leads'|'adSpend', label, value, unit, yesterday, source, sourceDay: 'YYYY-MM-DD', about } ],
  changed: string | null,
  builtAt: timestamptz | null,
  missed: { customers, period: 'YYYY-MM', source } | null,
  checkin: 'YYYY-MM-DD' | null }
```
- `value` is the number for `sourceDay` (the day before `day`: the last full day). `yesterday` is the number for the day before `sourceDay`, or null. A tile is only there when that day has a verified, client-visible number and its source is not listed as disconnected. Real zero = 0; missing = no tile.
- units: customers `customers`, leads `leads`, adSpend `CAD` (the client's own spend paid to Meta and Google). `about` is "A checked number for Tue 20 Oct."
- `missed` has no `back` field (you mentioned `back?`); it is not sent.
- `updating`: `tiles: []`, `changed: null`, `builtAt: null`, `missed: null`. Never an older day's content.

**`client_mark_opened(p_kind text, p_id text) returns timestamptz`**
Kinds: approval, update, message, work, results, billing, home. Client only (staff/view-as: 42501). First open per person per item is kept and returned. Unknown approval id: P0002. Bad kind or id: 22023. Call it when an approval card or dialog is opened.

**`client_welcome() returns jsonb`** `{ show: false }` or `{ show: true, title, text, href, button }`. Per Clerk user. Shows only on the first sign-in (no `touch_seen` visit older than 12 hours) and only when there is finished work: a waiting approval (`#/go/approval/<id>`, button "Review and approve", e.g. "Your first 3 posts are ready"), else the newest update (`#/go/update/<id>`, "See the update", e.g. "Your autumn menu page is live"), else the newest result (`#/go/results/<id>`, "See your numbers"). `href` is a hash route, not a full URL. Staff: 42501.

**`client_welcome_seen() returns timestamptz`** marks it shown for this person; never shows again.

Console (staff only): **`client_followups()`** returns rows `{tenant_id, last_seen_at, unread_from_team, next_checkin, checkin_due, pending_approvals, unopened_approvals, call_owner, call_reason, local_today}`. Staff RPCs: **`set_next_checkin(p_tenant uuid, p_next date, p_every_days int default null)`**, **`mark_checkin_done(p_tenant uuid)`** (next = local today + checkin_every_days). ## Decisions (documented choices)

- Check-in: new columns `tenants.next_checkin date` and `tenants.checkin_every_days int default 14` (not readable by clients directly; only through the RPCs). When `next_checkin` is empty, `doc.meeting.at` is used.
- Demo = `doc.demo`, `doc.tenantId` like `tnt_demo_*`, or a name starting "Bayleaf Kitchen". Test/internal = `doc.internal` or `doc.test` (the internal-tenant mark from the 2026-10-20 work). Demo rows are kept as status `logged`, never sent. Test rows go only to `test_inbox_email`; empty = `logged`.
- Staff messages left the old 2-minute batch (message_notifications) and go to `client_emails` at once, one email each. Client-to-team emails are unchanged.
- Update emails with no Settings > Emails switch of their own (work status, results, home items) are always sent; approvals follow `approvals`, website items follow `website`, Monday email follows `weekly`, billing items are `account` (always). A switch counts as off only when every known person at the restaurant turned it off.
- "Unread" = staff message newer than the latest `user_prefs.appearance.messagesSeenAt` of the restaurant's people (people = anyone with a `touch_seen` visit or who wrote from the dashboard), and not answered by the client after it. Reminders look back 14 days at most and are skipped at send time if seen or answered by then. The reminder is sent for messages too, not only questions.
- The question subject uses the sender's first name ("Karan has a question: ..."); "Karan" when the name is missing.
- The Monday email is queued when last week's summary row is first inserted (rebuilds and older weeks do not email).
